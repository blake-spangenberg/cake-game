# Tech stack
The settled stack for the browser proof of concept and beyond.

## Stack
| Layer | Pick |
|---|---|
| Core | Rust crate holding the simulation (`rapier3d` with `enhanced-determinism`, the grab, the knife) and the cut, compiled to WASM for the client and natively for the server. Toolchain pinned in `rust-toolchain.toml` |
| Client | TypeScript, Vite, Three.js (WebGL2, shadow maps), with the core loaded through `wasm-bindgen` |
| Server | Rust, `axum` with its WebSocket support on `tokio`, linking the core natively. Serves the client build and the WebSocket on one plain-HTTP port |
| HTTPS | The host's existing reverse proxy terminates TLS and routes to the server. Guests already reach the home machine |
| Assets | glTF 2.0 (`.glb`) |
| Tests | `cargo test` for the core, plus the determinism test below |
| Dev environment | Windows, `rustup` with the `wasm32-unknown-unknown` target, Node LTS for Vite, VS Code with `rust-analyzer` |

## Server authority
Clients are untrusted. The server replays every player's inputs in its own copy of that player's world and scores the cut it computes, so no one can fake a cut. Every player's cake and knife are independent of everyone else's, so no rollback is needed: the local player simulates instantly, and the server runs a round trip behind.
- The simulation steps at a fixed 60 Hz and counts ticks. Clients send tick-stamped inputs, never poses.
- Inputs are quantized before they enter the simulation: the client casts rays and eases controls in TypeScript, then sends and simulates the same fixed-point values. Nothing computed with JS `Math` functions reaches the core unquantized.
- `src/client/src/controls.ts` hand-encodes the core's input wire format, so it changes together with `src/core/src/input.rs`.
- Sim code must stay deterministic across native and WASM: transcendental math only through `libm` or nalgebra's own functions, no iteration over `HashMap` or `HashSet` (randomly seeded), no threads, no Rapier `parallel` or `simd` features. One exact Rapier version.
- `Cut!` carries its tick. The server replays to it, freezes, and cuts. Timeout is the server cutting at the round's final tick, and inputs stamped after it are dropped.
- Spectators receive poses streamed from the server's replay. A late joiner gets the current poses and the round state, with no input history.
- Desync is the one new failure mode: a divergent replay would score a cut the player never saw. The client sends a world-state hash about once a second, and the server logs any mismatch.
- Determinism test: one recorded input log replayed natively and in WASM must give the same world-snapshot hash at every checkpoint. `make test` runs it, so it reruns on every Rapier or Rust toolchain upgrade.

## Cut and weigh
Each model has uniform density, so grams are volume times a constant. Scoring clips the mesh's triangles against the cut plane and sums the signed tetrahedron volumes to a point on that plane, so the cap contributes nothing and needs no triangulation. Drawing the halves caps each cut face through the stencil buffer, which needs no cap geometry but, like scoring, depends on the mesh being closed. Real cap geometry (core-built or `manifold-3d`) waits until cut faces need textured layers.

## Asset pipeline
Most free models are not watertight or are built of overlapping parts, so `tools/bake-cake.sh <model.glb> <out.cake>` repairs and validates each one, and rejects what it cannot fix, to repair by hand or drop. Two steps:
- `tools/repair-model.py` (Python through `uv`, with `trimesh`, `pymeshfix`, `manifold3d`, `xatlas`, and `libigl`) welds vertices, closes holes only on pieces that are not already manifold, unions the pieces into one solid so overlapping boxes become their outer surface, drops specks under 1% of the volume, and stops where several large pieces remain (`--keep-largest` keeps one, as for a pair of shoes). It decimates a model over `--max-triangles` (40000 by default) by quadric edge collapse, since the bake's collider decomposition takes minutes on a quarter-million triangles. It then scales the longest side to `--size-m` (0.24 by default), centers the model over the stand, and rests it on y = 0. The repaired surface shares no UVs with the source, so its coloring is baked anew: `xatlas` lays the solid out on a fresh atlas of `--texture-size` texels (2048 by default, about 0.2 mm per texel), and each texel takes the color of the nearest source surface point (`libigl`), read from the source's texture, vertex colors, or material color at full detail. A source texture finer than the atlas is blurred to one atlas texel first so it averages out instead of aliasing. The glb keeps the solid split along its texture seams, each vertex naming the solid vertex it copies in a `_SOLID_VERTEX` attribute, and the texture as WebP (`EXT_texture_webp`). Per-model options cover what a source gets wrong for a cake: `--hollow` carves out the inside of a model whose counterpart is hollow, bridging openings such as a shoe's collar on a voxel grid so the hollow runs out through them; `--fill-unlit-underside` replaces a scan's black, never-lit bottom with the surface above it; `--recolor` turns hues and scales saturated colors; and `--hull-open-pieces` stands in a convex hull for an open-shell part that will not close, such as a guitar's neck. Thin open pieces that will not close (fins, strings, a propped lid) are dropped as trim rather than failing the repair. Headless Blender was the first plan, but `winget` could not download it, and these libraries need no install beyond `uv`
- `src/bake` (`cake-bake`) reads that glb, rejoins the seams into one closed mesh by the `_SOLID_VERTEX` ids (not by position, since a hollowed wall can put two sheets at the same place), splits the mesh into convex hulls with `parry3d`'s V-HACD, cuts each hull to at most `MAX_HULL_VERTICES` vertices by dropping the vertices whose loss costs the least volume, since a hull face with many vertices jitters on the table and never sleeps, and writes the `.cake` file. The core's `CakeModel::validate` is the gate: closed and outward-wound mesh, every side within `MAX_CAKE_EXTENT_M`, resting on y = 0 within the stand's plate, usable hulls

Mass and center of mass come from the render mesh when the world is built, so the hulls only carry collision. Baked cakes are tracked as brotli-packed `assets/cakes/<id>.cake.br` (`tools/cake-pack.mjs`, about half the raw size, since neither float positions nor the WebP texture compress much), and `make cakes`, which `make run` runs, unpacks the ones that changed into `build/public/cakes/`, the client's public directory, and deletes unpacked cakes whose source is gone. `src/client/src/cakes.ts` is each cake's single source of truth: its in-game name, credit, license, and repair options. `make test` checks that it lists exactly the packed cakes, and `tools/bake-cakes.sh [id...]` rebakes from it, after a pipeline change or a change to a cake's options. `tools/bake-cake.sh` packs an output named `*.cake.br`. The `.cake` file (`CakeModel::encode` and `decode`) is little-endian: `CAKE`, a version, the vertex, triangle, and hull counts and the texture's byte length, each hull's vertex count, then the mesh's positions, each hull's vertices, the triangle indices, and, unless the cake is plain, each triangle's three corner UVs as `u16` pairs and the WebP texture as encoded. UVs are per corner because a texture seam gives one vertex several UVs while the weighed mesh must stay closed. The core carries the texture without decoding it, and the client draws it with smooth normals creased where faces meet at over 60 degrees.

## Ruled out
- Bevy and Godot's web export: download size works against near-instant late joins, and Godot's physics promises no cross-platform determinism
- Babylon.js: more built in, but heavier, and its bundled Havok physics would go unused
- Jolt: its WASM build is deterministic only when compiled with `CROSS_PLATFORM_DETERMINISTIC`, which the prebuilt packages lack
- Trusted clients reporting their own poses: simpler and immune to desync, but open to cheating from dev tools
