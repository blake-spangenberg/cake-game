# Tech stack
The settled stack for the browser proof of concept and beyond.

## Stack
| Layer | Pick |
|---|---|
| Core | Rust crate holding the simulation (`rapier3d` with `enhanced-determinism`, the grab, the knife) and the cut, compiled to WASM for the client and natively for the server. A dated nightly toolchain pinned in `rust-toolchain.toml` (see Rust conventions) |
| Client | TypeScript, Vite, Three.js (WebGL2, shadow maps), with the core loaded through `wasm-bindgen` |
| Server | Rust, `axum` with its WebSocket support on `tokio`, linking the core natively. Serves the client build and the WebSocket on one plain-HTTP port, the build's files as the brotli or gzip copies it wrote beside them (`tower-http`'s `ServeDir`), so the server compresses nothing itself |
| HTTPS | The host's existing reverse proxy terminates TLS and routes to the server. Guests already reach the home machine |
| Assets | glTF 2.0 (`.glb`) |
| Tests | `cargo test` for the core, plus the determinism test below |
| Dev environment | Windows, `rustup` with the `wasm32-unknown-unknown` target, Node LTS for Vite, VS Code with `rust-analyzer` |

## Server authority
Clients are untrusted. The server replays every player's inputs in its own copy of that player's world and scores the cut it computes, so no one can fake a cut. Every player's cake and knife are independent of everyone else's, so no rollback is needed: the local player simulates instantly, and the server runs a round trip behind.
- The simulation steps at a fixed 60 Hz and counts ticks. Clients send tick-stamped inputs, never poses.
- Inputs are quantized before they enter the simulation: the client casts rays and eases controls in TypeScript, then sends and simulates the same fixed-point values. Nothing computed with JS `Math` functions reaches the core unquantized.
- `src/client/src/controls.ts` hand-encodes the core's input wire format, so it changes together with `src/core/src/input.rs`. Likewise `src/client/src/net.ts` and `src/server/src/protocol.rs` both encode that input and every other message in `protocol.md`, so they change together.
- Sim code must stay deterministic across native and WASM: transcendental math only through `libm` or nalgebra's own functions, no iteration over `HashMap` or `HashSet` (randomly seeded), no threads, no Rapier `parallel` or `simd` features. One exact Rapier version. Rapier's `enhanced-determinism` does not cover every dependency: glamx's 3x3 eigen solver calls std `acos` and `cos`, which parted the Marble Bust's native and WASM worlds through parry's mass properties, so the core computes a cake's mass properties itself. Parry's nonlinear shape casts and convex-polyhedron feature search still call std `sin` and `cos`, untraced to any divergence so far.
- `Cut!` carries its tick. The server replays to it, freezes, and cuts. Timeout is the server cutting at the round's final tick, and inputs stamped after it are dropped.
- Spectators receive poses streamed from the server's replay. A late joiner gets the current poses and the round state, with no input history.
- Desync is the one new failure mode: a divergent replay would score a cut the player never saw. The client sends a world-state hash about once a second, and the server logs any mismatch.
- Determinism test: one recorded input log replayed natively and in WASM must give the same world-snapshot hash at every checkpoint. `make test` runs it, so it reruns on every Rapier or Rust toolchain upgrade. `make upgrade` bumps both, with every other dependency, and ends with `make test`.

## Rust conventions
The owner asked to adopt the conventions of `https://www.namtao.com/rust/` for their strictness, where nothing here contradicts them, and to prefer the nightly toolchain.
- Lints: the root `Cargo.toml`'s `[workspace.lints.clippy]`, which every crate opts into, denies clippy's `pedantic` and `nursery` groups and the page's panic lints but those below. `clippy.toml` relaxes the panic lints in tests, as the page does. An exception is an `#[expect(lint, reason = "...")]` at the narrowest scope that reads well, which fails once nothing needs it. The broad ones are the Rapier boundary `sim/setup.rs` (f64 to f32 casts) and each example and integration test file (casts over small counts, and `unwrap` in test helpers, which `clippy.toml` does not reach).
- Left off, each for a rule here:
    - `suboptimal_flops` and `imprecise_flops`: their fixes, such as `mul_add` and `hypot`, round differently, which changes every hash, and call std math the determinism rules keep out of the simulation.
    - `expect_used`, `panic`, `unreachable`, and `indexing_slicing`: input is validated once where it enters and invariants are asserted inside, which is what an `expect` naming its invariant and indexing into a validated mesh do. A bare `unwrap` names no invariant, so `unwrap_used` stays.
    - `arithmetic_side_effects`: the integer arithmetic runs on indices and ticks bounded by validated input, so checking each operation would re-check it.
    - `as_conversions`: the pedantic cast lints already flag every lossy `as`, and the rest have no other std spelling, such as f64 to f32 for Rapier and the wire format's saturating quantizing.
    - The page's tools and libraries (nextest, bacon, devenv on Nix, `color-eyre`, `clap`): `cargo test` and the stack above already cover them.
- Toolchain: a dated nightly, `nightly-YYYY-MM-DD`, is one exact toolchain like a stable pin, so the determinism test guards it the same way. Nothing uses a nightly feature, so a stable pin still builds. `make upgrade` moves the pin to the newest nightly of the last two weeks that ships rustfmt, clippy, and the `wasm32-unknown-unknown` target, then `make test` reruns the native and WASM replay. Each bump's clippy finds a little differently, so expect to fix a few findings and remove `#[expect]`s it reports as unfulfilled: the move from 1.95 to nightly stopped `float_cmp` firing inside `assert_eq!`.

## Cut and weigh
Each model has uniform density, so grams are volume times a constant. Scoring clips the mesh's triangles against the cut plane and sums the signed tetrahedron volumes to a point on that plane, so the cap contributes nothing and needs no triangulation. Drawing the halves caps each cut face through the stencil buffer, which needs no cap geometry but, like scoring, depends on the mesh being closed. Real cap geometry (core-built or `manifold-3d`) waits until cut faces need textured layers.

## Asset pipeline
Most free models are not watertight or are built of overlapping parts, so `tools/bake-cake.sh <model.glb> <out.cake>` repairs and validates each one, and rejects what it cannot fix, to repair by hand or drop. Two steps:
- `tools/repair-model.py` (Python through `uv`, with `trimesh`, `pymeshfix`, `manifold3d`, `xatlas`, and `libigl`) welds vertices, closes holes only on pieces that are not already manifold, unions the pieces into one solid so overlapping boxes become their outer surface, drops specks under 1% of the volume, and stops where several large pieces remain (`--keep-largest` keeps one, as for a pair of shoes). It decimates a model over `--max-triangles` (40000 by default) by quadric edge collapse, or by merging edges within a tolerance where that breaks the shape, since the bake's collider decomposition takes minutes on a quarter-million triangles. It then scales the longest side to `--size-m` (0.24 by default), centers the model over the stand, and rests it on y = 0. The repaired surface shares no UVs with the source, so its coloring is baked anew: `xatlas` lays the solid out on a fresh atlas of `--texture-size` texels (2048 by default, about 0.2 mm per texel), and each texel takes the color of the nearest source surface point (`libigl`), read from the source's texture, vertex colors, or material color at full detail. A source texture finer than the atlas is blurred to one atlas texel first so it averages out instead of aliasing. The glb keeps the solid split along its texture seams, each vertex naming the solid vertex it copies in a `_SOLID_VERTEX` attribute, and the texture as WebP (`EXT_texture_webp`). Per-model options cover what a source gets wrong for a cake: `--hollow` carves out the inside of a model whose counterpart is hollow, bridging openings such as a shoe's collar on a voxel grid so the hollow runs out through them, and leaving solid where the walls alone would cut a part such as a shoe's tongue free; `--inside-color` paints the carved walls one plain color; `--fill-unlit-underside` replaces a scan's black, never-lit bottom with the surface above it; `--recolor` turns hues and scales saturated colors; `--trim-below` cuts away everything under a share of the model's height, leaving a flat bottom, for legs too thin to stand a cake on; `--plinth` stands a model that cannot stand on its own foot on a turned wood base, unioned into the solid and painted wood, with the base counted in `--size-m`; `--hull-open-pieces` stands in a convex hull for an open-shell part that will not close, such as a guitar's neck; `--join-within` stretches a part modeled a hair short of the body (a piano's leg under it) into it, then moves each part modeled standing a few millimeters off, such as a piano's pedal lyre, the short way onto it, trimming the wires on it no cake could hold, such as pedal rods; and `--first-use-vertex-order` numbers the solid's vertices in the order the glb first copies them, as `cake-bake` numbered the cakes it baked before it read `_SOLID_VERTEX`, so rebaking one of those keeps the vertex order that replays and scripts grab points by. Thin open pieces that will not close (fins, strings, a propped lid) are dropped as trim rather than failing the repair. trimesh reads a skinned mesh in its bind pose and ignores animation, so an animated model is first frozen at the pose the owner picked by `tools/pose-model.py` (Python with `numpy`), which samples the animation at `--time-s`, moves each vertex by its weighted joints, and writes a static glb with the UVs and textures unchanged. `tools/bake-cake.sh` runs it when given `--pose-s <seconds>`, which a cake's options in `cakes.ts` carry like a repair option, so a rebake reproduces the pose from the animated source. Headless Blender was the first plan, but `winget` could not download it, and these libraries need no install beyond `uv`
- `src/bake` (`cake-bake`) reads that glb, rejoins the seams into one closed mesh by the `_SOLID_VERTEX` ids (not by position, since a hollowed wall can put two sheets at the same place), splits the mesh into convex hulls with `parry3d`'s V-HACD, cuts each hull to at most `MAX_HULL_VERTICES` vertices, since a hull face with many vertices jitters on the table and never sleeps, and writes the `.cake` file. The cut keeps the vertices that leave the smallest worst gap to the part's extreme points, then pushes the hull out until the mesh reaches at most 1.5 mm outside it and never below its bottom, so a cake does not sink visibly into what it rests on. A cake whose hulls then float it on some side or bridge a wide gap takes the bake option `--trim-overhangs`: no corner is pushed more than 2 mm past the mesh, and a part whose hull reaches over 1 cm outside the mesh, such as the gap under a piano's keyboard, is split in two, up to 24 hulls a cake. That costs hulls and opens gaps of up to about 4 mm, so it is set per cake rather than for the set. The core's `CakeModel::validate` is the gate: closed and outward-wound mesh, every side within `MAX_CAKE_SIDE_M` and the extent bound within `MAX_CAKE_EXTENT_M`, resting on y = 0 within the stand's plate, usable hulls

Mass and center of mass come from the render mesh when the world is built, so the hulls only carry collision. Baked cakes are tracked as brotli-packed `assets/cakes/<id>.cake.br` (`tools/cake-pack.mjs`, about half the raw size, since neither float positions nor the WebP texture compress much), and `make cakes`, which `make run` runs, unpacks the ones that changed into `build/public/cakes/`, the client's public directory, and deletes unpacked cakes whose source is gone. `src/client/src/cakes.ts` is each cake's single source of truth: its in-game name, credit, license, and repair and bake options. `make test` checks that it lists exactly the packed cakes, and `tools/bake-cakes.sh [id...]` rebakes from it, after a pipeline change or a change to a cake's options. `tools/bake-cake.sh` packs an output named `*.cake.br`. The lobby's cake picker shows each cake as a 256-pixel WebP preview in `assets/previews/`, which `make previews` renders from the packed bakes in headless Edge on SwiftShader (`tools/render-previews.mjs` and the dev-only `previews.html`, through `puppeteer-core`), so they look the same from any machine. Each preview records the hash of the bake it shows in `sources.json`, and `make test` fails on a preview missing or older than its cake, so a rebake needs `make previews` after it. The `.cake` file (`CakeModel::encode` and `decode`) is little-endian: `CAKE`, a version, the vertex, triangle, and hull counts, the texture's byte length, and the count of distinct corner normals, each hull's vertex count, then the mesh's positions, each hull's vertices, the triangle indices, unless the cake is plain each triangle's three corner UVs as `u16` pairs and the WebP texture as encoded, and last the corner normals. UVs are per corner because a texture seam gives one vertex several UVs while the weighed mesh must stay closed. The core carries the texture without decoding it, and the client draws it with smooth normals creased where faces meet at over 60 degrees. The bake computes those normals, so a round's load spends no frame on them. Most of a vertex's corners share one normal, so the file holds each vertex's distinct normals once, folded onto an octahedron as two `u16` (within 1e-4 rad of the computed normal, far below what 8-bit color shows), and each corner's pick among them as a byte. A triangle of no area has no normal, so the bake collapses each such triangle's shortest edge, nanometers long after decimation, after fitting the hulls, which would otherwise come out different. `decode` accepts only its own version, so a format change rebakes every cake.

The client's fonts, Pacifico for titles and `Cut!` and Nunito for all other text, ship as WOFF2 subsets beside their SIL OFL licenses in `src/client/src/fonts/`, so no page loads a font service. `tools/subset-fonts.sh` rebuilds them from a pinned commit of Google's font repository. Neither font has a Reserved Font Name, which would forbid a subset from keeping the name; Lobster, the other script the owner was shown, has one.

## Ruled out
- Bevy and Godot's web export: download size works against near-instant late joins, and Godot's physics promises no cross-platform determinism
- Babylon.js: more built in, but heavier, and its bundled Havok physics would go unused
- Jolt: its WASM build is deterministic only when compiled with `CROSS_PLATFORM_DETERMINISTIC`, which the prebuilt packages lack
- Trusted clients reporting their own poses: simpler and immune to desync, but open to cheating from dev tools
