# Protocol
The WebSocket between the client (`src/client/src/net.ts`) and the server (`src/server/src/protocol.rs`), which change together. Each player holds one connection, at `ws` relative to the page so a reverse proxy can mount the game at any path. Text frames are JSON objects tagged by `type`. The two per-tick streams are binary frames, all little-endian.

Clients are untrusted, so the server bounds what one can cost it. A client message over 256 bytes closes its connection: the largest legitimate one, a join with a 24-character name and a seat token, is about 215. So does sending text messages faster than 10 a second after a burst of 30, since some, such as a host claim, cost a message to every player; a page sends a hash a second and a control message per click. A connection with 256 frames waiting to go out, about 8 s of pose frames, is disconnected as too slow, as is one whose frame takes 10 s to send. Connections hand their messages to the room through a queue of 1024 events; once it is full, a connection waits its turn and reads nothing from its socket meanwhile, so a flooding client slows only itself. Each event names its connection, and an event from a connection the room has dropped is ignored, even once a reopened page holds that connection's seat.

| From | Message | Carries |
|---|---|---|
| Client | `join` | The typed `name`, the `standup_preference`, 0 for first to give an update to 1 for last, and the `seat` token of this browser's last welcome or null, as the connection's first message. A name that is empty, over 24 characters, or holds a control character, or a preference outside 0 to 1, gets `error` and a closed connection |
| Client | `claim_host` | A `password`, which makes the sender host if it is `greylag`, even over a host still present, and otherwise gets `claim_refused`. Refused with `error` during a round |
| Client | `pick` | The host's `cake` for the next round, an id or `random`. Refused with `error` from anyone else, outside the lobby, or for a cake the server lacks |
| Client | `start` | Starts a round on the picked cake. Refused with `error` from anyone but the host or outside the lobby |
| Client | `return_to_lobby` | Ends the results for everyone. Refused with `error` from anyone but the host or outside the results |
| Client | `ready` | Sent once the round's cake has loaded |
| Client | input, binary | Per tick, the `u32` tick the input steps the world from, then `Input::encode`'s nine `i32` |
| Client | `cut` | The `tick` the world was at when `Cut!` was pressed, after that tick's inputs |
| Client | `hash` | `World::calc_hash` at `tick`, once a second, as a decimal string since a JSON number cannot hold every `u64` |
| Server | `welcome` | The connection's own `id` and its `seat` token, once |
| Server | `resume` | To a page reopened into its seat in the round, or to a playing page whose world parted from the server's: every tick its world has stepped as `runs` of `ticks` with one `input` in `Input::encode`'s values, and the `cut_tick` if it has cut, after the round's other messages |
| Server | `room` | `phase`, `host` (null while vacant), and `members`, whenever one changes. Never a member's standup preference |
| Server | `pick` | The next round's `cake`, always an id, and `is_random`, on joining the lobby and whenever it changes. A pick of `random` settles on a cake at once, so every page downloads and builds that cake in the lobby, hidden, and the start never rerolls it |
| Server | `claim_refused` | A `claim_host` had the wrong password |
| Server | `round` | The round's `cake`, `round_ticks`, and `players` as members, named as the round started, so a page joining after one left can still label their view. Anyone not listed spectates |
| Server | `sit_out` | The ids of the round's `players` whose page had not loaded the cake when the round started, just before `start`. They spectate instead |
| Server | `start` | Tick 0, `elapsed_ms` ago for a spectator who joined late |
| Server | `cut` | A player's cut `tick` and frozen `pose`, and the `cut_lower_m`, `cake_touch_lower_m`, and `is_cut_through` the cut animation needs, so every client can replay it. Never the score |
| Server | `play_over` | Every round player has cut, so the whistle blows. Sent once as it happens, never to a page that joins later |
| Server | pose, binary | During play, about 30 times a second, a 56-byte record per round player: `u32` id, tick, and flags (1 holding, 2 cut), then `f32` cake translation and rotation quaternion, knife tilt, lowering, and rest, and stand angle |
| Server | `judging` | The judging reveal, 3 s after the last round player cut: every player's `standings`, the random `order` they are judged in, the `scene_ms` each gets, and `elapsed_ms` since it began, for a page that joins during it. Each scene is built from that player's `cut` |
| Server | `results` | Every round player's `standings`, once the judging reveal ends, and the `standup` order of everyone in the room as members, spectators included |
| Server | `desync` | The client's hash at `tick` differs from the server's replay |
| Server | `error` | Why a message was refused |

## Round
The room moves from `lobby` to `loading` when the host starts, to `playing` once every player is `ready` or 10 s have passed, to `judging` 3 s after every player has cut, to `results` once the reveal has shown every player for 5 s each and held 1.5 s more (logged with the order as `judging order`), and back to `lobby` when the host returns everyone, with the pick preset to Random and settled anew. At the start, a connected page that has not sent `ready` sits the round out as a spectator, with a spectator's standup slot, and a round with no player left is called off back to the lobby; a page that left while the round loaded stays in it as a leaver, unless it reopens before the start, when it must send `ready` again like any page. The 3 s let every page's opponent views play the last cut's 2.2 s knife motion, timeouts included, and freeze with the check mark, so the whistle follows `play_over`, not `judging`, and every page has the time to prepare the scenes the cuts call for. The order is drawn once, on the server, so every page judges alike, and no one can claim host or end the reveal early. A player who joins in any phase but the lobby gets the round, its start, the cuts so far, and the judging or the results if they are showing, then spectates and plays the next round. A player whose page closes mid-round stays in the round: the server queues their last input with the hand let go and the knife raised, and steps their world on with it in time with the round's clock, with no grace, so it cuts itself as the round's time runs out and they are ranked like anyone. A round plays out even with every page gone, and a reveal or results no page is left to see give way to the lobby. No one hosts until someone claims it, and a host who leaves leaves the seat vacant, so a room whose host left during the results waits for a claim to return to the lobby.

A page whose connection closes leaves its seat held, and a `join` carrying that seat's token takes it back, with its id and its place in the round, until the player has gone an hour without doing anything themselves: a control message, a cut, or an input that differs from the one before. A token whose seat is still connected, as from a second tab, gets a new seat. The reopened page steps the `resume` runs again without sending them, cuts at `cut_tick`, then catches up to the round's clock as usual.

The standup order is settled once, as the results are: players choose in leaderboard order, those sharing a rank shuffled, then spectators in join order, each taking the open slot nearest their preference spread across all slots, the earlier of two equally near. A player joining during the results gets that order without a slot.

The server replays each player's messages in the order they arrived, at its own 60 Hz step. A message stamped ahead of the replay is reached by repeating the player's last input, and a stale input is dropped, both logged, one line per kind of message and replay tick in a step, so a burst of stale inputs logs once. An input or cut stamped more than 30 ticks (0.5 s) past the round's clock, the ticks of wall time since `start`, is refused and logged, one line per player and kind of message in a step, so no message makes one step replay a world far ahead. A malformed input frame is dropped, and logged at most one line per connection per step. A connected player's world never trails the round's clock by more than 2 s of grace: past that, it steps on with their last input, as for any tick not heard of, and inputs for those ticks that arrive later are stale. A stale input that differs from the one the server held means the page's world has parted from the server's, so the server sends it `resume`, at most once a second, putting off a parting within that second until it has passed: the page rebuilds its world from those steps and its own inputs since, which the server took as sent, swaps it in when caught up, and plays on, unless it cuts first. Stale inputs for ticks before that `resume` part nothing. So the deadline, the round's length plus the grace, finds every world cut at the round's last tick, and a client that went silent costs about one world step per server step rather than a whole round's in the deadline's one step. Inputs after a world's cut are dropped.

The client keeps to the server's clock, counted from when `start` arrived less its `elapsed_ms`. A tab switched away lets go of the cake and knife as a released mouse does: on hiding, the page steps and sends one tick with the hand let go and the knife at its rest, which the server holds while the tab is gone. Each frame it steps the newest few ticks with the live controls, and any older ones it missed, while its tab was hidden, its frames ran slow, or it reopened mid-round, with the input it sent last, which is what the server holds for a tick it has no input for. It sends every input it steps, so the server's world matches what the player saw whether those inputs arrive within the grace or the server held the same input meanwhile. The catch-up spends at most 40 ms a frame, and `Cut!` stays disabled until it ends. The judging takes over whatever a page was doing, so a player back after the deadline and still catching up sees the timeout cut the server scored in the reveal.

Standings rank a higher unrounded score first, and of equal scores the earlier cut. Cuts equal in both share a rank. Players who never touched the controls share a rank because their worlds run alike to the same timeout cut, and `has_touched` marks them.
