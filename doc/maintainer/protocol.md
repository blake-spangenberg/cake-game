# Protocol
The WebSocket between the client (`src/client/src/net.ts`) and the server (`src/server/src/protocol.rs`), which change together. Each player holds one connection, at `ws` relative to the page so a reverse proxy can mount the game at any path. Text frames are JSON objects tagged by `type`. The two per-tick streams are binary frames, all little-endian.

Clients are untrusted, so the server bounds what one can cost it. A client message over 256 bytes closes its connection: the largest legitimate one, a `?debug` page's join with a 24-character name and a seat token, is about 245. So does sending text messages faster than 10 a second after a burst of 30, since some, such as a host claim, cost a message to every player; a page sends a hash a second and a control message per click. A connection with 256 frames waiting to go out, about 8 s of pose frames, is disconnected as too slow, as is one whose frame takes 10 s to send. Connections hand their messages to the room through a queue of 1024 events; once it is full, a connection waits its turn and reads nothing from its socket meanwhile, so a flooding client slows only itself. Each event names its connection, and an event from a connection the room has dropped is ignored, even once a reopened page holds that connection's seat.

| From | Message | Carries |
|---|---|---|
| Client | `join` | The typed `name`, the `standup_preference`, 0 for first to give an update to 1 for last, `has_scrum_update` (true when left out), the `seat` token of this browser's last welcome or null, and `is_debug`, true from a page opened with `?debug` and otherwise left out, as the connection's first message. A name that is empty, over 24 characters, or holds a control character, or a preference outside 0 to 1, gets `error` and a closed connection. A name a connected player has gets `name_taken` and a closed connection |
| Client | `claim_host` | A `password`, which makes the sender host if it is `greylag`, even over a host still present, and otherwise gets `claim_refused`. Refused with `error` during a round |
| Client | `pick` | The host's `cake` for the next round, an id or `random`. Refused with `error` from anyone else, outside the lobby, or for a cake the server lacks |
| Client | `start` | Starts a round on the picked cake. Refused with `error` from anyone but the host or outside the lobby |
| Client | `return_to_lobby` | Ends the results for everyone. Refused with `error` from anyone but the host or outside the results |
| Client | `ready` | Sent once the round's cake has loaded |
| Client | input, binary | Per tick, the `u32` tick the input steps the world from, then `Input::encode`'s nine `i32` |
| Client | `cut` | The `tick` the world was at when `Cut!` was pressed, after that tick's inputs |
| Client | `hash` | `World::calc_hash` at `tick`, once a second, as a decimal string since a JSON number cannot hold every `u64` |
| Client | `add_bot`, `remove_bot` | From the host's `?debug` page, in any phase: adds a bot, or removes the newest. Refused with `error` from any other page |
| Client | `set_round_length` | From the host's `?debug` page: `round_s`, 1 to 600, the length of every round started from then on |
| Client | `set_bot_latency` | From the host's `?debug` page: `latency_ms`, 0 to 10000, how late each message between a bot and the room arrives, each way |
| Server | `welcome` | The connection's own `id` and its `seat` token, once |
| Server | `resume` | To a page reopened into its seat in the round, or to a playing page whose world parted from the server's: every tick its world has stepped as `runs` of `ticks` with one `input` in `Input::encode`'s values, and the `cut_tick` if it has cut, after the round's other messages |
| Server | `room` | `phase`, `host` (null while vacant), and `members`, whenever one changes. Never a member's standup preference |
| Server | `pick` | The next round's `cake`, always an id, its `round_ticks`, and `is_random`, on joining the lobby and whenever either changes. A pick of `random` settles on a cake at once, so every page downloads and builds that cake in the lobby, hidden, and the start never rerolls it |
| Server | `claim_refused` | A `claim_host` had the wrong password |
| Server | `name_taken` | A `join` named a player whose page is connected, then the connection closes. The page asks for another name |
| Server | `round` | The round's `cake`, `round_ticks`, and `players` as members, named as they started or joined it, so a page joining after one left can still label their view. Anyone not listed spectates |
| Server | `still_loading` | The ids of the round's `players` whose page has yet to load the cake, just before `start` and to a page joining mid-round after `start`. Pages show no view of them until `now_playing` |
| Server | `now_playing` | A round `player`, as a member, whose page loaded the cake after the round started, so every page adds their view |
| Server | `start` | Tick 0, `elapsed_ms` ago for a spectator who joined late |
| Server | `cut` | A player's cut `tick` and frozen `pose`, and the `cut_lower_m`, `cake_touch_lower_m`, and `is_cut_through` the cut animation needs, so every client can replay it. Never the score |
| Server | `play_over` | Every round player has cut, so the whistle blows, unless it already has: a page that has cut blows it as soon as it has heard of every other round player's `cut`, a round trip sooner. Sent once as it happens, never to a page that joins later |
| Server | pose, binary | During play, about 30 times a second, a 56-byte record per round player: `u32` id, tick, and flags (1 holding, 2 cut), then `f32` cake translation and rotation quaternion, knife tilt, lowering, and rest, and stand angle |
| Server | `judging` | The judging reveal, 3 s after the last round player cut: every player's `standings`, the `order` they are judged in (every miss first, the rest at random), and `elapsed_ms` since it began, for a page that joins during it. Each player's scene holds for `hold_ms`, counts for their entry in `count_ms` (3 s times the square of their score's share of a perfect one, 0 for a miss), and lasts `after_ms` more with the score up; every page lays the scenes end to end from these. Each scene is built from that player's `cut` |
| Server | `results` | Every round player's `standings`, once the judging reveal ends, and the `standup` order of everyone in the room as members, spectators included |
| Server | `desync` | The client's hash at `tick` differs from the server's replay |
| Server | `error` | Why a message was refused |
| Server | `debug` | To `?debug` pages only, on joining and whenever one changes: the next rounds' `round_s`, the room's count of `bots`, and their `bot_latency_ms` |

## Round
The room moves from `lobby` to `loading` when the host starts, to `playing` once every player in the room at the start is `ready` or 10 s have passed, to `judging` 3 s after every player has cut, to `results` once the reveal has played every player's scene, 1 to 4 s by score, and held 1.5 s more (logged with the order and each scene's count as `judging order`), and back to `lobby` when the host returns everyone, with the pick preset to Random and settled anew. The round starts on time even if no page has loaded: a page that has not sent `ready` stays in it, its world idling with the round's clock, keeps loading, and plays the time left once it sends `ready`, as a late joiner does, and one that never does is judged as untouched. A page that left while the round loaded stays in it as a leaver, unless it reopens before the start, when it must send `ready` again like any page. The 3 s let every page's opponent views play the last cut's 2.2 s knife motion, timeouts included, and freeze with the check mark, so the whistle follows `play_over`, not `judging`, and every page has the time to prepare the scenes the cuts call for. The order is drawn once, on the server, so every page judges alike, and no one can claim host or end the reveal early. A player who joins while the round loads, or plays until every round player has cut, joins it with a fresh world, gets the round, its start, `still_loading`, the cuts so far, and an empty `resume`, and plays once their page sends `ready`, stepping the ticks it missed with the idle input the server held for them; the start waits only for the players there when the host pressed Start, and one who joined since and left before it shows as a leaver through `now_playing`. A player who joins once every round player has cut, or during the judging or the results, gets the round, the cuts, and the judging or the results, then spectates and plays the next round. A player whose page closes mid-round stays in the round: the server queues their last input with the hand let go and the knife raised, and steps their world on with it in time with the round's clock, with no grace, so it cuts itself as the round's time runs out and they are ranked like anyone. A round plays out even with every page gone, and a reveal or results no page is left to see give way to the lobby. No one hosts until someone claims it, and a host who leaves leaves the seat vacant, so a room whose host left during the results waits for a claim to return to the lobby.

A page whose connection closes leaves its seat held, and a `join` carrying that seat's token takes it back, with its id and its place in the round, until the player has gone an hour without doing anything themselves: a control message, a cut, or an input that differs from the one before. A token whose seat is still connected takes it too, and the room closes the old connection: a page reloaded or navigated to another query string often joins before the server sees its old socket close, and a second tab of the same browser carries the same token. No two players in the room, connected or holding a seat, share a name, compared after trimming surrounding spaces and ignoring case. A `join` naming a held seat takes that seat over, token included, as if it had carried the token; one naming another connected player gets `name_taken`. The reopened page steps the `resume` runs again without sending them, cuts at `cut_tick`, then catches up to the round's clock as usual.

The standup order is settled once, as the results are: players choose in leaderboard order, those sharing a rank shuffled, then spectators in join order, each taking the open slot nearest their preference spread across all slots, the earlier of two equally near. A player who joined without a scrum update gets no slot, so the slots number only those with one. A player joining during the results gets that order without a slot.

The server replays each player's messages in the order they arrived, at its own 60 Hz step. A message stamped ahead of the replay is reached by repeating the player's last input, and a stale input is dropped, both logged, one line per kind of message and replay tick in a step, so a burst of stale inputs logs once. An input or cut stamped more than 30 ticks (0.5 s) past the round's clock, the ticks of wall time since `start`, is refused and logged, one line per player and kind of message in a step, so no message makes one step replay a world far ahead. A malformed input frame is dropped, and logged at most one line per connection per step. A page keeps to the round's clock from when `start` reached it, so its inputs arrive a round trip behind that clock even when nothing holds them up: the server takes the fewest ticks any of a page's inputs arrived behind the clock as that page's input lag, at most 3 s, and holds the page's world back by twice it on top of the grace, so a page far away is held up only by a stall, as a near one is. Twice, because a lost packet holds a TCP stream about a round trip longer while it is resent, which for a page 1 s away each way would alone use up the 2 s grace. A connected player's world never trails the round's clock by more than twice their input lag and 2 s of grace: past that, it steps on with their last input, as for any tick not heard of, and inputs for those ticks that arrive later are stale. A page shows the round for a round trip before `start` reaches it, so its player may move the cake from tick 0. So from a page's `ready` until its first input arrives, its lag counts as the most, 3 s, for as long as that hold lasts, 8 s of the round's clock, after which a page still silent counts as near. Only a page over 8 s of round trip away that acts in its first moments is resynced, once. A stale input that differs from the one the server held means the page's world has parted from the server's, so the server sends it `resume`, at most once a second, putting off a parting within that second until it has passed: the page rebuilds its world from those steps and its own inputs since, which the server took as sent, swaps it in when caught up, and plays on, unless it cuts first. Stale inputs for ticks before that `resume` part nothing. A step holds a world on by at most 30 ticks more than the clock advanced since the step before, so a late joiner's fresh world catches up over about a second, each step costing about 3 ms on a 40k-triangle cake, rather than stepping up to 170 ms of idle ticks at once. So the deadline, the round's length plus the grace and twice the page's input lag, finds every world cut at the round's last tick, even a late joiner's who joined on its last tick, and a client that went silent costs about one world step per server step rather than a whole round's in the deadline's one step. Inputs after a world's cut are dropped.

## Debug
A page opened with `?debug` joins with `is_debug` and hears `debug`; the room-wide debug messages are accepted only from the current host, in any phase, so a guest cannot change the room (owner, 2026-11-25): any other sender, a `?debug` guest included, gets `error` and changes nothing. Each change is logged with who made it. The page shows those controls only while it is host. `add_bot` gets `error` once the room holds 16 members, pages and bots together, as many as a round holds; a page joining is never refused for it. Bots are players the room itself plays, with ids from 2^30 up and names `Bot 1`, `Bot 2`, the lowest number free: in the room's member list, in every round from its start or, added mid-round, as a late joiner, sending `ready` and the inputs of the carry-and-sway script `bot-players.mjs` plays, then cutting at a random 50-95% of their time left. The bot latency delays each bot's `ready` by twice it and its inputs by twice it behind the round's clock, the round trip of a page that far away, and a bot never sends inputs more than 30 ticks ahead of its world. A removed bot's round plays on as a leaver's. A round length set mid-round applies from the next round, and in the lobby resends `pick`, whose `round_ticks` every page builds its preloaded round with. A page's own simulated latency stays in the page: `net.ts` holds every message it sends and receives that long, in order. For scripts, such a page's `window.setSimulatedJitterMs` strays each message's latency at random, and `window.holdSimulatedSends` holds its sends for a while as a lost packet's resend would, both keeping the order.

The client keeps to the server's clock, counted from when `start` arrived less its `elapsed_ms`. A tab switched away lets go of the cake and knife as a released mouse does: on hiding, the page steps and sends one tick with the hand let go and the knife at its rest, which the server holds while the tab is gone. Each frame it steps the newest few ticks with the live controls, and any older ones it missed, while its tab was hidden, its frames ran slow, or it reopened mid-round, with the input it sent last, which is what the server holds for a tick it has no input for. It sends every input it steps, so the server's world matches what the player saw whether those inputs arrive within the grace or the server held the same input meanwhile. The catch-up spends at most 40 ms a frame, and `Cut!` stays disabled until it ends. The judging takes over whatever a page was doing, so a player back after the deadline and still catching up sees the timeout cut the server scored in the reveal.

Standings rank a higher unrounded score first, and of equal scores the earlier cut. Cuts equal in both share a rank. Players who never touched the controls share a rank because their worlds run alike to the same timeout cut, and `has_touched` marks them.
